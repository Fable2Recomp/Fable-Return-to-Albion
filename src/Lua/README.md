# Native Lua Module

This module mirrors the launcher's top-level layout with dedicated `include`,
`src`, and `thirdparty` folders.

`refii_lua` builds the native helper layer and the vendored Lua 5.5 runtime
from `thirdparty/lua`.

`refii_lua_hooks` is linked directly into `refii_generated` so strong PPC hook
definitions can override autogenerated weak functions in the generated recomp
output.

`refii_lua_decompiler_workspace` is the reusable workspace decompiler library used by
the launcher installer after ISO extraction.

`refii-lua-decompiler-single` is the native Lua 5.1 single-file decompiler
built from the vendored `lua51` and legacy `luadec51` backend sources.
`refii-lua-decompiler` wraps the library for manual workspace-scale export so
the launcher can build `lua/...` without a Java dependency. The standalone
tool targets are no longer part of the default build and are emitted under
`out/build/.../tools/` only when you build them explicitly.

Current runtime CVars:
- `lua_use_native_handlers`
- `lua_trace_native_handlers`
- `lua_trace_script_loads`
- `lua_force_loose_banks`
- `lua_use_mod_overrides`
- `lua_trace_mod_overrides`
- `lua_mod_workspace_root`

Native handlers currently cover:
- `data/scripts/Startup/startup.lua`
- `data/scripts/Startup/audio.lua`

Loose Lua override flow:
- `lua_use_mod_overrides` now defaults to `true`, so the runtime will prefer host files from the extracted Lua workspace before the original banked guest loader runs unless you turn it off in `refii.toml`.
- The default workspace root is `<game_root>/lua`, which resolves to `assets/game/lua` for launcher installs.
- Override lookup is case-insensitive and currently checks `override/` first, then the public Lua workspace paths such as `scripts/`, `scripts_r/`, `gamescripts/`, `gamescripts_r/`, and `guiscripts/`.
- If a loose plaintext script fails guest compilation or execution, the hook now falls back to the original banked loader instead of hard-failing the load.
- `lua_mod_workspace_root` can point the runtime at a different extracted workspace without recompiling.

Tracing notes:
- `lua_trace_script_loads=true` now prefers recovered script keys over raw guest pointers when a Lua chunk header or extracted workspace hash can identify the script.

Decompilation notes:
- The native decompiler is best-effort today. The debug-rich `gamescripts/` bank yields the highest success rate.
- Retail aliases under `gamescripts_r/` are mapped back to their `gamescripts/` counterpart when available so the readable mirror can cover the runtime paths too.
- Chunks that crash or time out under source decompilation now fall back to readable disassembly under `_disasm/`, and `_manifest.tsv` records that status.
- Public Lua workspace files preserve the same relative paths the game expects under `data/`, but rooted at `lua/` instead.
- The installer keeps extracted bytecode under `lua/.source` so hash-based script-key recovery and parity work can still use the original chunks.
